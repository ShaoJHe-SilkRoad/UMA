## Admission conditions

Claude may become visible only after all of the following:

1. the user gives explicit Browser Sync consent;
2. the default browser family and exact companion are supported;
3. the exact current official personal Usage route is verified;
4. the page extractor validates expected usage landmarks and rejects login,
   billing, identity, chat, and project contexts;
5. a current bounded normalized message is accepted;
6. at least one account-level quota window is valid;
7. no credential, cookie, identity, broad page content, or private endpoint is
   accessed;
8. main panel and Desktop Assistant publish the same sanitized state.

An old cache alone cannot establish first admission. A later safely validated
cache may appear only as Cached/Stale until a new current observation becomes
Fresh.

The retained live classifications are:

## Final decision rules

PASS requires complete current-default-browser live proof, minimized extension
permissions, fail-closed extraction, bounded native messaging, regression and
package verification, removal of the rejected Keychain/OAuth runtime, and one
commit-exact package.

PASS WITH RISKS is allowed only when the current default-browser path passes in
full and a secondary browser family or store distribution remains unverified.
It is not allowed for missing live quota, failed login, excessive permissions,
remaining Keychain code, or private-data leakage.

FAIL is required if a usable observation cannot be produced without cookies,
login-page inspection, broad host access, a private endpoint, identity/billing
collection, or another rejected source class.

The current Safari path passed the live gate and is admitted. No historical
Claude route is a fallback. Automatic background refresh remains deliberately
unimplemented, and Chromium plus signed production/store extension
distribution remain unverified. Those are the bounded risks supporting PASS
WITH RISKS rather than an unconditional cross-browser PASS.

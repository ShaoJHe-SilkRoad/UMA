# M1A-G1 QA Issue Ledger

## QA-L01 — 已修复：认证标志解释相反

- **发现**：首次真实 `UsageStore` 读取收到已存在的账户对象，但被错误显示为“需要官方 Codex 登录”。
- **根因**：将 `requiresOpenaiAuth: true` 误当作账户不可用；已安装 app-server 对已认证受管会话也返回该值。
- **修复**：账户对象存在即表示可用；该布尔值不再作为拒绝条件。
- **验证**：直接真实协议探针、四阶段生产 Store 证据、协议回归和 65 项全量回归均通过。

## QA-L02 — 已修复：断开期间的陈旧本地扫描竞态

- **发现**：`refresh()` 或会话检查在等待 detached 本地扫描期间若被断开/撤销，恢复后仍可能启动账户或用量读取，并把已撤销的数据重新保留。
- **修复**：操作 epoch 的 `defer` 在扫描前安装；扫描后必须同时通过当前 epoch 与同意状态检查，才可更新本地快照或调用客户端。异步刷新信号/连接状态回读后也再次检查。
- **验证**：两个受控 held-reader 测试分别覆盖账户检查和用量读取；两者均证明 0 次错误重启、1 次断开、无保留本地数据。另有并发刷新测试证明第二次手动刷新被合并。全量回归 65/65 通过。

## QA-L03 — 已修复：app-server 帧格式与模式约束

- **发现**：服务需要 JSON-line JSON-RPC，而不是 Content-Length 帧；账户/额度/用量形状也必须与 schema 一致。
- **修复**：生产 transport 改为受限 JSON-line；账户读取使用 `{}`，其余两个读取明确使用 `null` 参数；未知或超限消息不保留。
- **验证**：合成 HOME 协议测试、真实只读协议探针、协议契约回归均通过。

## QA-L04 — 已关闭：真实稳定性与打包菜单栏验收

- **状态**：通过。
- **验证**：Gate A 已完成 1,200 秒、3 次实时读取和 21 个样本；期间始终只有一个受监控的 app-server 子进程，并完成受控终止验证。Gate B 随后通过原生 macOS Accessibility 打开唯一临时包的状态栏面板，确认经脱敏的真实聚合值可见，并完成两次真实 Refresh。
- **恢复性验证**：只终止该包拥有的 app-server 子进程后，包本身保持存活，诚实显示“早先数据/刷新失败”状态；选择包内 Retry 后仅创建一个替代子进程并恢复新鲜数据，未重启包、未产生状态栏项目或子进程重复。
- **结论**：未发现需要修复的状态栏注册、面板打开、Refresh 可操作性或子进程生命周期缺陷。

## QA-L05 — 已修复：首次提供方失败隐藏有效本机来源

- **发现**：首次提供方读取失败、但受限本机会话元数据已可用时，`UsageStore` 正确保留本机快照，但失败呈现将 `showsRealData` 固定为 false，导致面板隐藏可用的“本机”来源。
- **修复**：失败呈现接收既有真实快照状态；只要本机来源可用，现有数据面板继续显示其归属和新鲜度。
- **验证**：新增 `firstProviderFailureStillPresentsIndependentLocalActivity` 回归；最终暂存快照的 M1A-G1 聚焦回归 15 项及全量回归 26 项均通过。

## QA-L06 — 已修复：打包脚本可能从调用方脏工作树构建

- **发现**：脚本先解析自身根目录，但未在执行 `swift build` 前切换目录；从仓库外调用时，SwiftPM 会使用调用方工作树。
- **修复**：打包前显式切换至 `ROOT_DIR`。
- **验证**：从外部调用最终暂存源码副本，构建日志仅包含已暂存的 M1A-G1 目标；唯一临时包通过 plist 与严格签名检查，并由原生 AX 打开其状态栏面板。

## QA-L07 — 已关闭：原生菜单栏续验

- **状态**：通过，无需产品修复。
- **验证**：对已接受临时包的 AXMenuBarItem 执行 AXPress 后，出现一个包所属面板；脱敏分类器确认真实百分比、重置/新鲜度和用量摘要均可见。两次真实 Refresh 都观察到过渡、完成和可见状态更新。
- **恢复性验证**：受控终止唯一直属 app-server 子进程后，包仍存活并诚实显示 Retry；包内 Retry 恢复新鲜值且只创建一个替代子进程。最终原生计数为一个包进程、一个可归属状态栏项目、一个连接器和一个活跃直属子进程。
- **非缺陷说明**：System Events 对 accessory 包没有普通 window 1（-1719）。这不影响已成功的 AX 菜单栏路径，也不构成状态栏注册、面板、Refresh 或子进程生命周期缺陷。

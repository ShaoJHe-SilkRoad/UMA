# UMA M5A Claude Assistant Handoff

## Accepted predecessor

M5DBG-G1 accepts the main-app provider order:

`Codex → Claude Code → WorkBuddy`

Claude Code remains excluded from Desktop Assistant. Codex and WorkBuddy retain
their accepted Assistant behavior.

## M5A boundary

M5A may begin only under a new explicit Founder instruction. It must preserve:

- the official local status-line source and strict allowlist;
- provider-owned authentication with no UMA credential access;
- one socket listener and one shared Claude connector;
- current five-hour and seven-day window semantics;
- one shared used-to-remaining conversion;
- health-check-only shared Manual Refresh behavior;
- failure isolation from Codex and WorkBuddy;
- exact settings backup, repair, disable, and restoration behavior;
- stable main-app ordering;
- one versioned, owner-only sanitized last-valid Claude quota record;
- independent five-hour and seven-day cache expiry;
- Fresh / Cached / Stale / Waiting semantics with no provider activity on
  restore;
- neutral cached/stale alert behavior and stable selected-window restoration;
- no prompt, response, session, transcript, task, tool, or raw payload access.

M5A must independently define Desktop Assistant layout, compact typography,
localization, accessibility, visibility, cadence, and lifecycle acceptance.
This handoff does not implement or authorize those changes.

M5A must not broaden the cached schema, persist raw status-line payloads, repeat
the used-to-remaining conversion, treat cache restoration as usage, or add
Claude to Desktop Assistant without a new explicit Founder instruction.

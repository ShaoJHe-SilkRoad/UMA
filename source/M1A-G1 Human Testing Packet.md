# M1A-G1 人工测试包：Codex 双来源用量连接器

## 本次状态

M1A-G1 自动化验收已完成：真实官方 app-server 的只读账户/额度/用量协议、1,200 秒子进程稳定性、生产 `UsageStore` 的首次连接和两次刷新、子进程终止后的包内 Retry 恢复、已打包菜单栏面板的脱敏真实值、最终暂存快照的 26 项离线回归，以及唯一临时包的 plist 与严格签名检查均已通过。

本包仅供你做可选的人工复核；不要求再次进行长期实时探针，也不要向本包输入任何凭据。

## 目的与边界

本包验证两个相互独立的只读来源：

1. **账户来源**：已安装官方 Codex CLI 的 app-server，固定顺序为 `account/read`、`account/rateLimits/read`、`account/usage/read`。
2. **本机来源**：仅扫描 `~/.codex/sessions` 与 `~/.codex/archived_sessions` 中 JSONL 的受限尾部元数据，推导最近会话 token 与“本机 API 等价估算”。它不是账户账单、额度或提供方用量。

监控器不会读取密码、令牌、Cookie、钥匙串、授权数据库、进程内存、提示词、消息或工具内容；不会启动浏览器、不会代表你登录，也不会打开或覆盖已安装应用。

- 自动化证据只保留了经脱敏的聚合状态和结构性进程结果；未保留账户身份、原始响应、会话标题、提示词或 Cookie。

## 操作步骤

1. 在 Finder 选择“前往 → 前往文件夹”，粘贴上述完整路径并手动打开临时包；确认只出现一个监控器菜单栏图标。
2. 打开面板，明确确认你希望监控器读取本机会话元数据，然后选择“连接”。若不授权，界面必须保持“未授权”，且不显示伪造的 0。
3. 已登录时，确认账户来源显示为可用并展示真实限额/用量。未登录或读取失败时，确认其状态清楚说明失败，而不是显示为 0。
4. 确认本机来源独立显示可用/不可用、捕获时间与覆盖率；账户首次读取失败但本机来源已可用时，面板仍应显示本机数据和其归属；本机会话不可用时账户来源仍应保留。
5. 在不重启临时包的情况下手动刷新两次。确认每次完成后新鲜度或捕获时间更新；若刷新失败，旧的真实账户数值必须标为较早数据，而不是被清空或伪造成 0。
6. 关闭面板后重新打开两次。确认始终只有一个图标，外框完整，底部“账户来源/本机来源”状态行未被裁切。
7. 确认“最近任务”只显示通用的本机 Codex 会话、时间与 token 数；不得出现会话标题、提示词、路径、账号或原始 JSON。
8. 确认“Token Cost (Est.)”只称为 API 标准价/估算，不被称为 Codex 账单或账户用量。退出临时包即可结束本地检查。

## 通过标准

- 两个来源都分别标明来源、范围、捕获时间、新鲜度/保留状态与覆盖信息。
- 账户未授权、缺失或失败绝不显示为 0；任何一方异常都不抹掉另一方已验证的数据。
- 无浏览器、无外部应用启动、无凭据访问、无安装包覆盖、无发布行为。
- 刷新和短暂故障恢复不需要重启临时包，也不会重复计入本机成本。
- 菜单栏项目、连接器子进程和面板在重复打开/恢复后均不重复出现。

## 3. Why Antigravity is M6

Google Antigravity is the strongest current next-provider candidate because:

- the official CLI and Antigravity 2.0 share the same core agent engine and settings;
- provider-managed Google authentication is handled by Antigravity;
- official `/usage` and `/quota` commands expose current model-quota information;
- current official CLI capability supports structured, non-interactive read-only output;
- the official changelog states read-only print commands create no agent turn, spend no quota, and leave no conversation;
- the quota schema supports remaining fractions and reset metadata;
- no browser extension, copied token, Keychain read, or private endpoint is required;
- Antigravity becomes provider four, allowing complete multi-provider validation before Cursor triggers the five-provider forced-Minimalist transition.

## 6. Official source decision

### 6.1 Preferred source — Tier L3

```text
Official Antigravity CLI
→ read-only print `/usage` or `/quota`
→ structured JSON
```

This is classified as:

```text
official read-only CLI
```

It may perform a provider-owned network quota refresh internally. UMA receives no credential.

### 6.2 Secondary evidence — Tier L2

The official status-line schema can corroborate quota field semantics:

```text
quota.<bucket>.remaining_fraction
quota.<bucket>.reset_time
quota.<bucket>.reset_in_seconds
```

M6 v1 does not install a status-line relay when the print-mode source works.

### 6.3 Optional Credits source

The official `/credits` print result may be accepted as an optional second channel or expanded detail only after M6-G1 proves:

- exact current spendable balance;
- stable structured schema;
- no billing or purchase fields required;
- no change to WorkBuddy credit semantics;
- total channel count at most two.

Quota support is not blocked by Credits rejection or deferral.

### 6.4 Prohibited sources

- unofficial local language-server protocol without an official contract;
- internal Google endpoints;
- third-party OAuth/token files;
- copied provider credentials;
- local browser/session data;
- activity-derived estimated balance;
- manual values.

## 7. Source-admission contract

M6-G1 returns one of:

```text
GO
CONDITIONAL GO
SETUP REQUIRED
NO-GO
```

### 7.1 GO

Require:

- official `agy` executable present;
- supported structured print capability present;
- provider-managed authentication usable;
- `/usage` or `/quota` returns a current structured result;
- at least one valid quota bucket;
- remaining and reset semantics are explicit;
- read creates no agent turn, conversation, or quota spend;
- identity/workspace/private fields are avoidable;
- output is bounded and deterministically decodable;
- live value can be compared to Antigravity's own view;
- source survives repeated read and process teardown.

### 7.2 CONDITIONAL GO

Allowed when:

- at least one valid account/model quota bucket is supplied;
- one optional reset or optional credits detail is absent;
- primary remaining value is still honest;
- privacy and lifecycle pass.

### 7.3 SETUP REQUIRED

Use when:

- CLI is absent;
- installed CLI lacks the required print capability;
- provider-managed login is incomplete;
- feature update is required;
- the source contract itself has not failed.

### 7.4 NO-GO

Use when:

- only copied credentials or private endpoints work;
- read-only command spends quota or creates provider work;
- output cannot be bounded without identity/workspace content;
- remaining semantics are ambiguous;
- only local estimates exist;
- the current account mode supplies no usable quota;
- automated reads inevitably launch login browser without user action;
- source is unstable or unsafe after repair attempts.

## 9. Data contract

### 9.1 Quota window

```text
bucketID
safeLabel?
remainingPercent
resetEpoch?
resetInSeconds?
observationTime
sourceVersion
```

### 9.2 Explicit semantic mapping

If the source supplies `remaining_fraction`:

```text
remainingPercent = remaining_fraction × 100
```

If a separately documented source supplies `used_percentage`:

```text
remainingPercent = 100 - used_percentage
```

Do not infer used-versus-remaining from numeric range.

### 9.3 Validation

- finite values;
- explicit range;
- no silent clamp;
- missing is unavailable;
- reset values bounded;
- unknown fields discarded;
- future schema fails closed;
- no private data enters normalized models.

### 9.4 Multiple buckets

- preserve independent provider bucket IDs;
- preserve current reset scope;
- do not sum or split pools;
- do not hard-code current model lineup;
- use centralized Maximum Decrement for compact selection;
- retain deterministic provider order.

### 9.5 AI Credits

Credits remain native Credits.

Do not:

- convert Credits to percentage without complete total;
- use plan grant as current balance;
- combine Credits with model quota;
- let Credits override percentage windows.

## 11. Refresh and freshness

### 11.1 Default cadence

```text
launch read
→ wait 5 minutes after completion
→ next read
```

Minimum interval:

```text
3 minutes
```

### 11.2 Coalescing

- one timer;
- one in-flight process;
- manual and scheduled triggers coalesce;
- successful manual read resets next interval;
- no catch-up burst;
- no rapid retry;
- no rendering-owned reads.

### 11.3 Admission

```text
supported CLI
+ usable provider-managed authentication
+ current successful structured read
+ at least one valid quota bucket
= visible Google Antigravity
```

Installed status alone does not admit.

### 11.4 Cached and stale

Persisted state, if used, must remain hidden on cold launch until a current read succeeds.

Cached/Stale:

- does not create a Maximum Decrement sample;
- does not trigger low-quota alerts;
- never overwrites a newer Fresh result;
- is cleared on auth/account uncertainty;
- remains provider-specific.

### 11.5 Disconnect

Disconnect:

- cancels timer and process;
- clears UMA-owned normalized snapshot;
- removes Antigravity presentation;
- does not sign the user out;
- does not modify provider keyring or settings.

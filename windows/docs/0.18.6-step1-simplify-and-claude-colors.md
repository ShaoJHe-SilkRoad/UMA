# AUV Windows 下一版 · 步骤 1：简化 Claude 操作流程，Claude 额度条颜色与 Codex 一致

状态：设计稿（2026-11-11），交给单独的执行会话实现。基线：`main` `a0086ec`（0.18.5 已发布）。分支：`windows-0.18.6`。

## 1. 额度条颜色与 Codex 一致

**现状：**颜色由 `LowRemainingPolicy.Resolve(id, plan, …)`（`windows/src/AUV.Windows.Core/AllowancePresentation.cs`）决定。Codex 有套餐名（plus/pro），按阈值显示绿色或红色；Claude 的浏览器读数没有套餐名，于是一直是中性蓝。

**改为：**Claude 用与 Codex 相同的绿/红规则。

| 情况 | 规则 |
|---|---|
| 已知 Claude 套餐（Max / Pro） | 保持现有阈值：Max 10%、Pro 20% |
| 套餐未知（目前浏览器读数都属于这种） | 采用 Codex Plus 的阈值：剩余 < 20% 为红色，否则为绿色 |
| 无读数、估算值、不可用 | 不变（中性 / 隐藏） |

- 只改颜色判定，不改条的形状、尺寸和绘制方式（`AllowanceRow`、`DetailQuotaBar` 的代码不动）。
- 主窗口智能体列表的填充色、详情页的两条额度条、托盘面板、桌面浮窗都会随之从蓝色变为绿/红。这是数据颜色的变化，桌面浮窗的布局与外观设计不变。
- 测试：`AllowanceTests` 中 claude + 未知套餐的用例由 Neutral 改为 Normal/Low，并补充 19.9% / 20% 边界用例。

## 2. 简化 Claude 浏览器伴侣的操作流程

0.18.5 实测中的摩擦点：
- 要勾选开关，再点“设置”，然后过一到两个确认框；
- 要自己复制文件夹路径、打开扩展页；
- 每次更新后要点“更新”，再到每个浏览器手动重新加载扩展；
- 浏览器、读取位置等选项一直摆在面前；
- 主窗口的 Claude 页在未设置时只有一行文字。

### 2.1 主窗口内一键开始

Claude 未开启或未设置时，Claude 页的“用量”卡片显示一个行动卡：

> **连接 Claude** —— 通过 Chrome 或 Edge 读取 Claude 的 5 小时与每周额度。[连接]

点“连接”只弹**一个**确认框。说明内容不变：复制到哪里、只写当前用户的注册表、不需要管理员权限。确认后自动完成：开启同步 → 复制文件 → 注册。

- 已有注册指向的是 AUV 自己的旧伴侣时，直接替换，不再询问。判断方法：清单 `name` 是 `com.silkrd.auv.claude_browser`，同目录有 `AUV.BrowserHost.exe` 和格式正确的 `host-config.json`。
- 只有真正的第三方注册才额外询问。

### 2.2 三步清单，实时打勾

Claude 设置页和行动卡展开后显示同一份清单，状态自动更新：

| 步骤 | 何时打勾 | 旁边的按钮 |
|---|---|---|
| ① 已为 Chrome 和 Edge 注册 | Set Up 成功 | — |
| ② 在浏览器中加载扩展 | 管道收到该浏览器的合格连接（握手成功） | **在 Chrome 中加载** / **在 Edge 中加载**：复制扩展文件夹路径到剪贴板 → 打开该浏览器的扩展页 → 显示提示条“开启开发者模式 → 加载已解压的扩展程序 → 在地址栏按 Ctrl+V 粘贴路径” |
| ③ 已登录 claude.ai | 第一次精确读数成功 | **打开 claude.ai**：在所选浏览器中打开 `https://claude.ai`，由用户自己登录，AUV 不碰凭据 |

三步都打勾后，清单收起为一行“已连接 · Chrome · 上次读数 HH:MM”。

### 2.3 更新自动完成

- **AUV 启动时：**如果打包的伴侣比已安装的新，自动更新（只涉及 AUV 自己的文件和注册），不再需要点“更新”。失败时才显示原因和“重试”按钮。
- **扩展自动重新加载：**协议新增命令 `umaClaudeReloadCompanion`（`auvCompanionCommand` 允许的命令中加入此项，只能由 AUV 发出）。
  - AUV 握手时发现扩展的构建标识与已安装伴侣不同（通道已通、身份不符），就发送这个命令。
  - 扩展收到后调用 `chrome.runtime.reload()`。解压加载的扩展会从同一文件夹重新读取文件，这样就换成了新版本。
  - 重新加载间隔至少 10 分钟，防止反复重载。
- **一次性过渡：**0.18.5 的扩展还不认识这个命令。从 0.18.5 升级时仍需手动重新加载一次，提示要明确说明这一点。之后的升级就全自动了。

### 2.4 设置页精简

- Claude 设置主区只保留：三步清单 / 连接状态、**立即同步**、**移除伴侣**。
- “浏览器”“读取位置”“浏览器未运行时询问”移进可折叠的“高级”分组（默认收起）。
- 文件夹路径输入框、复制路径、打开文件夹也放进“高级”，因为“在 Chrome 中加载”已经代替了它们。

### 2.5 失败原因可直接处理

Claude 卡片显示失败原因时，附一个对应按钮：

| 原因 | 按钮 |
|---|---|
| 需要登录 | 打开 claude.ai |
| 需要网站访问权限 / 扩展需重新加载 | 打开扩展页 |
| 等待浏览器 | 打开 Chrome / Edge（复用现有的最小化启动） |
| 页面布局无法识别 | 只显示说明，不放按钮 |

## 实现记录（2026-11-11）

与设计一致，以下几点是实现时的具体取舍，请审阅：

- **重新加载请求有两条路径。**设计写的是“通道已通、身份不符”时发送（协调器握手发现构建不同）。但升级后最常见的情况是：浏览器里还在运行旧扩展和它启动的旧辅助程序，旧辅助程序带着旧的生成 ID 连上管道，被 AUV 以 `generationMismatch` 拒绝，通道根本不会“通”。所以 AUV 在拒绝回执之后再写一帧 `umaClaudeReloadCompanion`，0.18.6 起的辅助程序收到 `generationMismatch` 后最多再读这一帧（2 秒）并只转发这一种命令。两条路径共用一个限频器（每个浏览器 ≥10 分钟，`CompanionReloadThrottle`），扩展端另有自己的 10 分钟间隔，且读取进行中不会重新加载。
- **一次性过渡：**0.18.5 的扩展和辅助程序都不认识这个命令，所以从 0.18.5 升级仍需手动重新加载一次；“不同构建”的提示文字和用户指南都写明了这一点，提示旁有“打开扩展页”按钮。
- **启动时自动更新**只在“同步已开启、已安装伴侣、打包的构建号比已安装的大”时进行（按数字比较，不降级）。“移除伴侣”会关闭同步，所以移除后不会被自动重新注册。
- **“连接”后不立即读取：**此时扩展还没加载，立即读取只会弹出“打开浏览器？”。浏览器一连上就会读取。
- **清单第 2、3 步的状态保存在设置中**（`ClaudeBrowser.LoadedBrowsers`、`ClaudeBrowser.ExactReadingSeen`，缺省为空 / false，0.18.5 的设置文件照常读取）；“移除伴侣”会清空它们。
- **“通过浏览器伴侣同步 Claude”开关仍保留**，放在“高级”里，用于暂停同步而不删除注册。
- 颜色规则只对精确读数（`Percentage`）生效；套餐未知的估算值仍为中性色。
- 新增可选检查 `--claude-check-dir <dir>`（需 `--offline` 和隔离的 `--settings-path`）：用合成伴侣包和一次性的 `HKCU\Software\AUV-Test-…` 键走完“连接 → 清单 → 已连接”，并截取中英文的 Claude 页和 Claude 设置；结束后删除该键和临时文件。加 `--claude-check-before` 只截图。
- **2026-11-11 更新（D6a，用户决定“Inside AUV install folder”）：**伴侣改为直接使用 AUV 安装文件夹中的 `BrowserCompanion`，不再复制到 `%LOCALAPPDATA%`。上面的“启动时自动更新（比较构建号、复制新文件）”因此改为“启动时把注册从其他 AUV 文件夹改指到本文件夹”，清单第 2 步按扩展文件夹记录，换文件夹后重新出现。详见 `chrome-extension-plan.md` 末尾的“决策更新”。
